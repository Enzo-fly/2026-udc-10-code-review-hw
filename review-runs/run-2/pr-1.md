# Рев'ю pr-1: Сторінкування для списку позик

**Вердикт:** Блокує злиття
**Знахідок:** 4 (critical: 0, high: 1, medium: 3, low: 0)

## Знахідки

### 1. [К7] [high] Перша сторінка (`page = 1` за замовчуванням) пропускає перші `pageSize` позик

- **Де:** `app/src/loans.js:30-32` (hunk `@@ -26,6 +26,13 @@`)
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це порушення:** нумерація сторінок за замовчуванням починається з `1`, але зсув
  рахується як `page * pageSize`, тобто як для нумерації з нуля. Сценарій: бібліотекар
  викликає `listLoansPage(db, iryna)` без параметрів на засіяних даних (7 позик) →
  `start = 20`, `items = []`, хоча `total = 7`. На 3 000+ позиках UI, що йде сторінками
  1, 2, 3 …, ніколи не покаже позики з індексами 0–19. Це неправильна поведінка на
  звичайних вхідних даних (тому `high`), і сторінкування за К7 фактично не працює.
- **Що виправити:** `const start = (page - 1) * pageSize;` (і валідувати `page` як ціле
  `>= 1`, див. знахідку 2); додати тест, що перша сторінка повертає перші записи.

### 2. [К7] [medium] Розмір сторінки не обмежений і не валідується — некоректні `page`/`pageSize` дають усе одразу або перекриття

- **Де:** `app/src/loans.js:30-33` (hunk `@@ -26,6 +26,13 @@`)
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
    return { items: all.slice(start, start + pageSize), page, pageSize, total: all.length };
  ```
- **Чому це порушення:** К7 вимагає максимум `pageSize` і щоб некоректні значення не
  віддавали весь список. Сценарії: `{ page: 0, pageSize: 100000 }` → усі 3 000+ позик за
  раз (саме те, від чого PR мав захистити UI); параметри з query-рядка як рядки
  `{ page: "1", pageSize: "20" }` → `start = 20`, `start + pageSize = "2020"` →
  `slice(20, "2020")` віддає 2 000 рядків; дробовий `page: 0.5` → сторінки перекриваються;
  від'ємні значення тихо дають `[]` замість помилки.
- **Що виправити:** привести й перевірити параметри: `page` і `pageSize` — цілі
  (`Number.isInteger`), `page >= 1`, `1 <= pageSize <= MAX_PAGE_SIZE` (напр. 100), інакше
  кидати помилку (або обрізати до максимуму); додати тести на `0`, від'ємне, дробове,
  рядкове значення і на перевищення максимуму.

### 3. [К6] [medium] Нова експортована функція `listLoansPage` без запису в `CHANGELOG.md`

- **Де:** `app/src/loans.js:30` (hunk `@@ -26,6 +26,13 @@`)
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ```
- **Чому це порушення:** К6 — нова публічна функція в `src/` (сигнатура з `{ page,
  pageSize }` і відповідь `{ items, page, pageSize, total }`) — це зміна API, яка має бути
  в `app/CHANGELOG.md` у тому самому PR. Диф `CHANGELOG.md` не змінює, тож споживачі API не
  дізнаються ні про функцію, ні про нумерацію сторінок і межі `pageSize`.
- **Що виправити:** додати запис у `app/CHANGELOG.md`: `listLoansPage(db, user, { page,
  pageSize })` → `{ items, page, pageSize, total }`, з якої цифри нумеруються сторінки,
  максимальний `pageSize`, хто має доступ.

### 4. [К8] [medium] Новий тест не перевіряє `items` і не впав би на неправильній реалізації

- **Де:** `app/test/loans.test.js:15-20` (hunk `@@ -12,6 +12,13 @@`)
- **Цитата:**
  ```js
  test("paged list reports the total and the page it returned", () => {
    const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
    assert.equal(res.total, 7);
    assert.equal(res.page, 1);
    assert.equal(res.pageSize, 20);
  });
  ```
- **Чому це порушення:** тест перевіряє лише `total` і відлуння вхідних `page`/`pageSize`,
  але не вміст сторінки. Він зелений на поточній реалізації, де `items` порожній
  (знахідка 1), — тобто не ловить головну поломку. Немає й тесту, що учасник через
  `listLoansPage` бачить лише свої позики, та тестів на межі `pageSize` (К7).
- **Що виправити:** додати `assert.deepEqual(res.items.map((l) => l.id), [1, 2, 3, 4, 5, 6, 7])`
  для першої сторінки; тест з `pageSize: 3` на сторінки 1/2/3 (`[1,2,3]`, `[4,5,6]`, `[7]`);
  тест для учасника (`olya` → `[1, 2, 7]`); тести на некоректні `page`/`pageSize`.
