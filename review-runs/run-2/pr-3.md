## Знахідки

### 1. [К1] [critical] Експорт контактів усіх учасників доступний будь-якому учаснику

- **Де:** `app/src/members.js:12` (hunk `@@ -7,6 +7,14 @@ export function listMembers(db, user) {`)
- **Цитата:**
  ```js
  export function exportMembersCsv(db, user) {
    if (!user) throw new AccessDenied();
  ```
- **Чому це порушення:** К1 вимагає перевірки ролі не м'якшої, ніж у сусідів. Сусідня `listMembers` віддає лише імена й ролі і вже вимагає `requireRole(user, STAFF)`; `memberCard` дає учаснику лише його власну картку. Нова функція віддає **email і телефон усіх** учасників, але перевіряє тільки `!user`. Сценарій: `exportMembersCsv(db, { id: 1, role: "member" })` повертає CSV з `taras@example.invalid,+380000000002`, контактами Марка, бібліотекарки й адміна — витік персональних даних усіх учасників будь-якому зареєстрованому користувачу.
- **Що виправити:** замінити `if (!user) throw new AccessDenied();` на `requireRole(user, STAFF);` (або вужчий набір ролей, якщо звірку робить лише адмін).

### 2. [К2] [high] Експорт email/телефонів не записує жодного звернення в журнал доступу

- **Де:** `app/src/members.js:14` (hunk `@@ -7,6 +7,14 @@ export function listMembers(db, user) {`)
- **Цитата:**
  ```js
    const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
  ```
- **Чому це порушення:** К2 — функція, що повертає email або телефон, викликає `logAccess(db, user, memberId, purpose)` по одному запису на кожного учасника, чиї дані віддано. Тут віддаються контакти 5 учасників (на засіяних даних), а `db.accessLog` після виклику лишається порожнім. Аудит «хто і навіщо дивився мої дані» зламано: масове вивантаження всіх контактів не залишає слідів. `logAccess` уже імпортовано в модулі й використовується в `memberCard`.
- **Що виправити:** для кожного рядка викликати `logAccess(db, user, m.id, "members-csv-export")` (осмислений `purpose`) і додати тест, що `db.accessLog` містить рівно `[[3, 1, …], [3, 2, …], …]` — по одному запису на кожного учасника.

### 3. [В5] [high] Поля CSV не екрануються: кома, лапка, перенесення рядка, формули

- **Де:** `app/src/members.js:14` (hunk `@@ -7,6 +7,14 @@ export function listMembers(db, user) {`)
- **Цитата:**
  ```js
    const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
    return [header, ...lines].join("\n");
  ```
- **Чому це порушення:** В5 — дані, що йдуть назовні (CSV), екрануються під формат. Значення просто склеюються через `,`. Сценарії: ім'я `Приклад, Оля` дає 6 колонок замість 5 і зсуває email у колонку `phone`; ім'я з перенесенням рядка розриває запис на два рядки; ім'я `=HYPERLINK("http://…","x")` або `+380…`/`-…`/`@…` на початку клітинки виконується як формула при відкритті файлу в табличному редакторі (CSV/formula injection). Ім'я вводиться користувачем, тож це звичайні вхідні дані, а файл призначений саме для відкриття людьми під час звірки.
- **Що виправити:** додати функцію екранування клітинки: якщо значення починається з `=`, `+`, `-`, `@` (або табуляції/`\r`) — додати префікс `'`; якщо містить `,`, `"`, `\n` чи `\r` — обгорнути в лапки й подвоїти внутрішні `"`. Додати тест з таким ім'ям.

### 4. [К9] [medium] Тест відмови перевіряє лише анонімного користувача, а не учасника

- **Де:** `app/test/members.test.js:43` (hunk `@@ -32,3 +32,14 @@ test("reading a card is recorded in the access log", () => {`)
- **Цитата:**
  ```js
  test("CSV export refuses an anonymous caller", () => {
    assert.throws(() => exportMembersCsv(createDb(), null), AccessDenied);
  });
  ```
- **Чому це порушення:** К9 — тест має відхиляти саме ту роль, яку треба. Для функції з контактами всіх учасників критичний випадок — звичайний учасник (`olya`), як у тесті `listMembers`. Тест з `null` проходить на поточній, надто відкритій реалізації (знахідка №1), тож не ловить головну проблему доступу.
- **Що виправити:** додати `assert.throws(() => exportMembersCsv(createDb(), olya), AccessDenied);` (разом з виправленням №1).

### 5. [К8] [medium] Новий тест формату перевіряє лише заголовок і кількість рядків

- **Де:** `app/test/members.test.js:39-40` (hunk `@@ -32,3 +32,14 @@ test("reading a card is recorded in the access log", () => {`)
- **Цитата:**
  ```js
    assert.equal(lines[0], "id,name,email,phone,role");
    assert.equal(lines.length, 6);
  ```
- **Чому це порушення:** К8 — тест має перевіряти конкретний результат. Тест пройде на неправильній реалізації, яка пише порожні чи переставлені поля (наприклад, `[m.id, m.name, m.phone, m.email, m.role]` або `undefined` замість телефону), бо вміст рядків даних не перевіряється. Також не перевіряється екранування (№3) і журнал доступу (№2).
- **Що виправити:** перевірити щонайменше один рядок даних дослівно, напр. `assert.equal(lines[1], "1,Оля Приклад,olya@example.invalid,+380000000001,member");`, і додати випадок з комою/лапкою/формулою в імені.
