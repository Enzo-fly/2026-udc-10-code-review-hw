# Рев'ю pr-1: PR-1: Сторінкування для списку позик

**Вердикт:** Блокує злиття
**Знахідок:** 5 (critical: 0, high: 2, medium: 3, low: 0)

## Знахідки

### 1. [К10] [high] Зсув на одну сторінку: `page = 1` пропускає перші `pageSize` записів

- **Де:** `app/src/loans.js:31` (hunk `@@ -26,6 +26,13 @@`)
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це порушення:** сторінки 1-базові (значення за замовчуванням `page = 1`), але
  зміщення рахується як `page * pageSize`, а не `(page - 1) * pageSize`. Виклик за
  замовчуванням (`page: 1, pageSize: 20`) повертає записи 21–40, а записи 1–20 не
  повертає жодна сторінка з `page >= 1`. На тестовій базі (7 позик) `listLoansPage(db, iryna)`
  повертає `items: []` при `total: 7`, тож у UI буде порожньо. Опис PR каже, що додано
  «сторінки», але код віддає неправильні сторінки. Це спростовує опис (К10) і є
  неправильною поведінкою (severity `high`).
- **Що виправити:** `const start = (page - 1) * pageSize;` і тест, який перевіряє
  `items` першої та наступної сторінок (див. №2).

### 2. [К8] [high] Новий тест не перевіряє `items` і проходить на зламаній реалізації

- **Де:** `app/test/loans.test.js:15-20` (hunk `@@ -12,6 +12,13 @@`)
- **Цитата:**
  ```js
  test("paged list reports the total and the page it returned", () => {
    const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
    assert.equal(res.total, 7);
    assert.equal(res.page, 1);
    assert.equal(res.pageSize, 20);
  });
  ```
- **Чому це порушення:** тест перевіряє лише `total` і два поля, які функція просто
  повертає з аргументів (`page`, `pageSize`). Головний результат функції, `items`, він не
  перевіряє, тому проходить і тоді, коли `items` порожній через помилку №1. Тест не впав
  би на неправильній реалізації, тож за К8 він нічого не перевіряє.
- **Що виправити:** перевіряти конкретний вміст, наприклад
  `assert.deepEqual(listLoansPage(db, iryna, { page: 1, pageSize: 3 }).items.map((l) => l.id), [1, 2, 3])`
  і для `page: 2` → `[4, 5, 6]`, `page: 3` → `[7]`.

### 3. [К7] [medium] Розмір сторінки не обмежено, некоректні `page`/`pageSize` не відхиляються

- **Де:** `app/src/loans.js:29-33` (hunk `@@ -26,6 +26,13 @@`)
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
    return { items: all.slice(start, start + pageSize), page, pageSize, total: all.length };
  ```
- **Чому це порушення:** К7 вимагає максимального розміру сторінки, а некоректні значення
  не мають віддавати все одразу. Що відбувається з поточним кодом:
  `{ page: 0, pageSize: 1e9 }` або `pageSize: Infinity` віддає всі 3 000+ рядків одним
  запитом, тобто саме те, від чого PR мав захистити. `page: -1` дає від'ємний `start`,
  і `slice` повертає хвіст списку. Дробові значення (`page: 1.5`) і рядки з query-параметрів
  (`"2"` → `"2" * 20 = 40`, але `start + pageSize` = `"4020"`) дають непередбачувані зрізи.
  `NaN` тихо повертає порожню сторінку.
- **Що виправити:** перевіряти, що `page` і `pageSize` — цілі числа, `page >= 1`,
  `1 <= pageSize <= MAX_PAGE_SIZE` (наприклад, 100), інакше кидати помилку або обрізати до
  меж. Додати на це тести.

### 5. [К9] [medium] Немає тесту з відмовою в доступі для нової функції

- **Де:** `app/test/loans.test.js:15-20` (hunk `@@ -12,6 +12,13 @@`)
- **Цитата:**
  ```js
    const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
  ```
- **Чому це порушення:** `listLoansPage` бере перевірку доступу з `listLoans`:
  анонімного відхиляє, а учасник бачить лише свої позики. Тест є тільки для
  бібліотекаря. Немає тесту, що `listLoansPage(db, null)` кидає помилку, і немає тесту,
  що учасник (`olya`) не отримує чужих позик і що `total` рахує лише його записи. Якщо
  колись замінити `listLoans(db, user)` на прямий `db.loans`, жоден тест цього не помітить.
- **Що виправити:** додати `assert.throws(() => listLoansPage(createDb(), null), …)` і
  тест, що для `olya` `items.map((l) => l.id)` дорівнює `[1, 2, 7]`, а `total` дорівнює `3`.

## Питання до автора

- JSDoc і опис кажуть «для персоналу / staff UI», а функцію може викликати й учасник
  (отримає свої позики). Так задумано, чи `listLoansPage` має бути staff-only через
  `requireRole(user, STAFF)`? Якщо staff-only, потрібен тест з `AccessDenied` для учасника.
- Звідки прийдуть `page`/`pageSize`: з query-рядка (тоді це рядки) чи вже як числа?
  Від цього залежить, де саме робити перетворення й валідацію.
