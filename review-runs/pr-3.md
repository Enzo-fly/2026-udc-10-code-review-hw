## Знахідки

### 1. [К1] [critical] `exportMembersCsv` відкрита для будь-якого учасника — він вивантажує email і телефони всіх

- **Де:** `app/src/members.js:12` (hunk `@@ -7,6 +7,14 @@`)
- **Цитата:**
  ```js
  export function exportMembersCsv(db, user) {
    if (!user) throw new AccessDenied();
  ```
- **Чому це порушення:** К1 — нова функція не може бути відкритішою за сусідів. Сусідня `listMembers` віддає лише `id, name, role` і все одно вимагає `requireRole(user, STAFF)`; `memberCard` дозволяє учаснику бачити тільки власну картку. Нова функція перевіряє лише наявність користувача. Сценарій: `exportMembersCsv(createDb(), { id: 1, role: "member" })` → повертає CSV з email і телефонами всіх 5 учасників, включно з персоналом. Це витік персональних даних. Додатково спростовує твердження опису «Без користувача — відмова, як і скрізь» (К10): «скрізь» у цьому модулі — це перевірка ролі, а не лише наявності користувача.
- **Що виправити:** замінити `if (!user) throw new AccessDenied();` на `requireRole(user, STAFF);`, як у `listMembers`.

### 2. [К2] [high] Експорт email і телефонів без жодного запису в журнал доступу

- **Де:** `app/src/members.js:14` (hunk `@@ -7,6 +7,14 @@`)
- **Цитата:**
  ```js
    const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
    return [header, ...lines].join("\n");
  ```
- **Чому це порушення:** К2 — функція, що повертає email/телефон, викликає `logAccess(db, user, memberId, purpose)` по одному запису на кожного учасника, чиї дані віддано. Тут `logAccess` не викликається взагалі. Сценарій: бібліотекарка викликає `exportMembersCsv(db, iryna)` → `db.accessLog` лишається `[]`, хоча контакти 5 учасників вивантажено. На питання «хто й навіщо дивився мої дані» журнал не відповість.
- **Що виправити:** у `map` для кожного `m` викликати `logAccess(db, user, m.id, "members-csv-export")`. Додати тест: після експорту `db.accessLog.map((e) => [e.by, e.memberId, e.purpose])` дорівнює `[[3,1,"members-csv-export"], …, [3,5,"members-csv-export"]]`.

### 3. [В5] [high] Поля CSV не екрануються: коми, лапки, перенесення рядків і формули ламають файл

- **Де:** `app/src/members.js:14` (hunk `@@ -7,6 +7,14 @@`)
- **Цитата:**
  ```js
    const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
  ```
- **Чому це порушення:** В5 — дані, що йдуть назовні в CSV, екрануються під формат. Значення склеюються через `","` без лапок. Сценарії: ім'я `Приклад, Оля` зсуває колонки (email потрапляє в стовпчик `phone`); ім'я з `\n` розриває запис на два рядки; ім'я `=HYPERLINK("http://…","клік")` або `+380…`/`@…` при відкритті файлу в Excel/LibreOffice виконується як формула (CSV injection). Файл призначений саме для відкриття людьми «для звірки з громадою».
- **Що виправити:** додати хелпер екранування: кожне поле, що містить `,`, `"`, `\r` або `\n`, брати в лапки, а `"` подвоювати; значенням, що починаються з `=`, `+`, `-`, `@` (а також табуляції чи `\r`), додавати префікс `'`. Додати тести на ім'я з комою, лапкою, перенесенням рядка і `=` на початку.

### 4. [К8] [high] Тест формату не перевіряє вміст рядків і пройде на неправильній реалізації

- **Де:** `app/test/members.test.js:36` (hunk `@@ -32,3 +32,14 @@`)
- **Цитата:**

Реалізація, що переставляє `email` і `phone`, пише в кожен рядок `undefined` або губить роль, цей тест пройде. Твердження опису «Тест на формат файлу додав» підтверджене лише частково.
- **Що виправити:** перевірити `assert.deepEqual(lines, [...])` з повним очікуваним вмістом (принаймні `lines[1] === "1,Оля Приклад,olya@example.invalid,+380000000001,member"`), а також тести на екранування (знахідка 3).

## Питання до автора

- К7: експорт віддає всіх учасників одним рядком без обмеження. Для звірки це, мабуть, очікувано, але чи погоджено виняток з правила про сторінкові списки? Якщо ні, потрібна сторінкова версія з обмеженим `pageSize` або явне рішення команди.
- Чи потрібні в експорті email і телефон для всіх ролей, зокрема для персоналу (`librarian`, `admin`)? Чи вистачить для звірки учасників з роллю `member`?
- Роздільник рядків `\n` чи `\r\n` (RFC 4180)? Чи потрібен BOM, щоб Excel коректно відкрив кирилицю?
